# H1 · Crear una solicitud

- **Issue:** —
- **Estado:** Aprobada
- **Aprobada por:** Andrés Londoño · 17/11/2026

## Historia
Como usuario quiero crear una solicitud con título y descripción para registrar una petición.

## Alcance
- Incluido: crear una solicitud mediante `POST /requests`; recortar `title` y `description` antes de validarlos y guardarlos; inicializar el estado y generar el identificador y la fecha de creación; almacenar las solicitudes en memoria.
- Fuera de alcance: consultar, listar, modificar o eliminar solicitudes; cambiar su estado; persistir datos fuera de memoria.

## Criterios de aceptación
1. **Dado** un cuerpo válido con `title` y `description`, **cuando** se envía a `POST /requests`, **entonces** la API devuelve `201` con `id`, `title`, `description`, `status: "open"` y `created_at`; `id` no está vacío y `created_at` es una fecha ISO 8601 válida.
2. **Dado** un cuerpo sin `title`, **cuando** se envía a `POST /requests`, **entonces** la API devuelve `400` con un objeto JSON que contiene una propiedad `error` de tipo texto.
3. **Dado** un cuerpo sin `description`, **cuando** se envía a `POST /requests`, **entonces** la API devuelve `400` con el formato de error común.
4. **Dado** un `title` y una `description` con espacios al principio o al final y contenido no vacío, **cuando** se envía a `POST /requests`, **entonces** la API recorta esos espacios antes de validar y guardar, y devuelve ambos valores recortados.
5. **Dado** un `title` o una `description` que, después de recortar espacios al principio y al final, queda vacío, **cuando** se envía a `POST /requests`, **entonces** la API devuelve `400` con el formato de error común.
6. **Dado** un título que, después de recortarlo, tiene de 1 a 100 caracteres, **cuando** se envía a `POST /requests`, **entonces** la solicitud se crea con `201` y se devuelve el título recortado; si tiene 101 caracteres, la API devuelve `400`.
7. **Dado** una descripción que, después de recortarla, tiene hasta 1000 caracteres, **cuando** se envía a `POST /requests`, **entonces** la solicitud se crea con `201` y se devuelve la descripción recortada; si tiene 1001 caracteres, la API devuelve `400`.
8. **Dado** que `title` o `description` tiene un tipo distinto de texto, o el cuerpo no contiene JSON válido, **cuando** se envía a `POST /requests`, **entonces** la API devuelve `400` con un objeto JSON que contiene una propiedad `error` de tipo texto.
9. **Dado** un cuerpo válido que contiene propiedades adicionales, **cuando** se envía a `POST /requests`, **entonces** la API ignora esas propiedades y no las incluye en la respuesta.
10. **Propuesta, pendiente de decidir:** **Dadas** dos peticiones válidas con los mismos valores de `title` y `description`, **cuando** se envían ambas, **entonces** las dos se crean con `201` y reciben identificadores distintos; se permiten solicitudes duplicadas.

## Contrato de la API
| Método | Ruta | Cuerpo | Respuesta correcta | Errores |
|---|---|---|---|---|
| `POST` | `/requests` | Objeto JSON con `title: string` y `description: string`, ambos obligatorios. Se recortan los espacios al principio y al final antes de validar y guardar. `title` debe tener entre 1 y 100 caracteres y `description` entre 1 y 1000 caracteres, una vez recortados. Las propiedades adicionales se ignoran. | `201 Created`; objeto JSON con `id: string`, `title: string` y `description: string` recortados, `status: "open"` y `created_at: string` en formato ISO 8601. Las propiedades adicionales del cuerpo no se devuelven. | `400 Bad Request` para campos ausentes, vacíos tras recortar, tipos inválidos, valores que exceden los límites y JSON mal formado; cuerpo JSON `{ "error": "..." }`. No se fija el texto del mensaje. |

## Casos límite y dudas abiertas
- **Duplicados:** Propuesta, pendiente de decidir: permitir solicitudes repetidas y generar un `id` diferente para cada creación.
- Los espacios al inicio y al final de ambos textos se recortan primero; los valores que queden vacíos se rechazan.
- Los límites se evalúan después del recorte: título de 100 caracteres aceptado y de 101 rechazado; descripción de 1000 caracteres aceptada y de 1001 rechazada.
- Los errores de validación son `400` y siguen el formato común `{ "error": "..." }`; los tests no comparan el texto del mensaje.
- La respuesta debe incluir una fecha parseable como ISO 8601. No se fija zona horaria en la historia ni en el modelo orientativo.
- Las propiedades adicionales del cuerpo se ignoran y no aparecen en la respuesta.
